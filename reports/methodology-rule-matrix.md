# Methodology Rule Matrix — Evidence Audit
> Evidence grades: A direct BTC daily evidence; B Bitcoin-specific but different configuration/frequency; C general time-series/ML empirical; D method/theory; E adaptation. Grades rate paper fit, not correctness. Search is not exhaustive.

| M03 | Daily granularity | E: Phase 2 / study design | Source provides daily bars; literature includes daily and hourly but does not compare frequency for this RQ. | Chosen research scale, not literature-optimized. | Keep daily provisionally; no claim it is optimal. **PROVISIONAL** |

| M09 | Validation 90 days | B: [3]; [1] | Bysik uses 3-month validation; Youssefi uses 6 months. | Conflicting precedents; daily/hours differ. | 90d plausible but insufficient to lock; define tuning purpose. **PROVISIONAL** |

| M12 | Selector XGBoost | B/C: [1], [10] | Youssefi compares MI, RFE, Random Forest importance—not XGBoost Gain. | M13 | Gain importance | D: Chen & Guestrin [10], XGBoost API [31] | Gain measures training loss reduction attributed to splits; Weight/Cover/Total Gain differ. | Model-dependent; correlated indicators can exchange/split credit. | Treat as operational ranking, not intrinsic feature relevance. **UNSUPPORTED as uniquely justified** |
| M14 | Top-K; pilot selected K=10 | B/E: [1],[3] | Youssefi selected 20 from >130 after an empirical complexity/performance check; Bysik Appendix uses one feature in each of 10 groups, Jaccard diagnostic. | Neither supports K=10 for this pool/selector. [7] | Chance-corrected overlap `(rN-k²)/(k(N-k))`; requires same set cardinality k and fixed universe N; random expected overlap maps to 0. | Useful complement; invalid comparison if K varies or universe changes. | Keep only if equal fixed K and N; implementation test. **PROVISIONAL** |

| M18 | XGBoost forecaster | B/C: [1],[10] | Gradient boosting algorithm; crypto work uses other selectors/models. | Good tabular baseline; same-family selector/forecaster can induce dependence in design. | Candidate baseline, no superiority claim. **PROVISIONAL** |
| M19 | Zero-return naive baseline | D/E: forecasting convention | For return target, constant zero is a clear no-change benchmark; it is not “price persistence” although equivalent to price no-change. | BTC precedent not independently established in reviewed records. | Keep and call zero-return baseline; consider train-mean alternative only if prespecified. **PROVISIONAL** |
| M20 | XGBoost pilot settings: 120 trees, depth3, eta .05, lambda1 | E: pilot implementation | Hyperparameters fixed in code; pilot mixed relative errors. | Pilot output is not evidence for tuning choice. | Not final; freeze or tune only within chronological train/validation. **UNSUPPORTED** |
| M21 | MAE | C/D: Hyndman & Athanasopoulos [11] | Mean absolute error, same unit as target; linear penalty. | Appropriate return units; less dominated by extremes than squared error. | Retain as descriptive error metric. **PROVISIONAL** |
| M22 | RMSE | C/D: [11] | Root mean squared error; larger errors receive quadratic weight. | Appropriate but sensitive to BTC tail events; pair with MAE. | Retain, do not use alone. **PROVISIONAL** |

| M24 | Block bootstrap | D: Künsch [13], Politis & Romano [14] | Moving/stationary block resampling addresses dependent stationary observations under assumptions. | Does not automatically solve dependence from estimated, overlapping windows; block length/unit must be defined. | Candidate inference tool only, not yet specified. **REQUIRES DECISION** |

| M26 | Multiplicity | D: Elmakias [4] / statistical design | Several metrics and two stability measures yield multiple pairwise tests; no adjustment implemented in pilot. | Small window count magnifies false positives. | Preregister one primary association; adjust/report secondary analyses. **REQUIRES DECISION** |
| M27 | Leakage prevention | A: project source code/tests | Target shifted one day; trailing features; XGB selector trained on train; prefix-truncation test passes. | Tests support implementation, not every future code path. | Keep chronological nesting, persist source/feature assertions. **PROVISIONAL** |
